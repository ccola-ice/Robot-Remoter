# 字体、长按与日历时钟

2026-09-21，针对设置字体不清楚、方向键不能长按、日期时间不正确的反馈更新。

## 界面与操作

参数设置和 NRF 设置的列表编号、名称、值统一采用 32 px 加粗样式：中文使用原有 32×32 点阵，ASCII 使用原有 16×32 点阵。增加一像素笔画，不再按数值长度自动缩成 16 px。名称和值的列宽固定，40 项参数及合法极值均检查了完整显示；固件版本行只显示版本，编译日期仍可在系统信息查看。标题、辅助说明和底栏保留字号层级。

上/下短按立即移动一项。持续按住约 0.5 秒开始连发，初始间隔 120 ms，持续到 1.5 秒后间隔 60 ms。松手、切换页面、进入或退出编辑、切换日期时间字段时取消旧连发。连发只保留一个待处理事件，绘制耗时不会造成松手后的积压跳动。OK 和 BACK 保持单次动作。

新入口为 **设置 → 日历时钟**，设置分类现在有参数设置、NRF 无线、日历时钟三项。

- 日历浏览：上/下切换月份，长按快速翻月；蓝色表示已校时的今天。
- 按 OK 打开操作选择，再用上/下选择“回到本月”“设置日期时间”或“GPS 校时”。
- 手动设置：依次调整年、月、日、时、分、秒，OK 进入下一项。最后选中“保存日期时间”并按 OK 才写入 RTC。BACK 放弃草稿，月末会随月份和闰年自动限制。
- GPS 校时：使用当前有效、未过期的北京时间。无有效 GPS 时间时提示等待，不写入无效日期。

所有日期均为公历，范围 2000—2099 年。界面按北京时间 UTC+8 使用；没有加入农历或其他时区选择。右上角分两行显示日期/星期、时分秒，即使秒数相同，修改日期或校时状态也能刷新。

## 时间不正确的原因和修复

原 RTC 首次初始化把 `__DATE__` / `__TIME__` 写成当前时间；编译时刻与烧录、使用时刻并不相同。原初始化还会在普通重启时重复配置 LSE 和初始化 RTC；ST 库的 `RCC_LSEConfig()` 会先关闭振荡器。这会干扰应当持续运行的后备时钟。

主板使用 X2 32.768 kHz 晶振，具备 CR1220 后备电池与 VBAT 网络。新服务保留正常运行的 LSE、分频和日期，普通重启不再重新停振或重写日期。旧版本留下的日期保留供查看和修改，但会标为“未校时”。全新、无有效日期的 RTC 使用 2000-01-01 作为明确未校时的起点。

手动或 GPS 设置成功后，保存独立的校时来源标记。读取日期时间采用一致快照；写入年月日和时分秒使用同一个 RTC 初始化窗口并检查读回结果。错误时钟源、分频或 12 小时制配置会修复，并尽量保留可表示的原日期，但不继续宣称其准确。

**原有 GPS 自动校时保留。** `gps_accept_time()` 对有效、未过期的 NMEA 时间转换一次 UTC+8 后调用 `RTC_SynchronizeCalendar()`。未校时的 RTC 会建立 GPS 时间；已经校时且偏差不超过一秒时不反复写入，偏差较大时会自动校正并标记 GPS 来源。日历里的 GPS 按钮是额外的显式校时入口。单纯浏览日历、修改草稿或取消，不会主动写 RTC；后台 GPS 服务仍按上述规则运行。

升级后若显示“未校时”，可手动设置一次，或等待有效 GPS 自动校时。实际断电保持还取决于板上后备电池的状态。

## 验证与构建

- ARM Compiler 5.06，按当前 EIDE 配置完整编译 100 个源文件通过；ROM 329.21 KiB，RAM 81.80 KiB。保留原有 12 个第三方/旧代码警告，本轮改动无新增编译警告。
- 生产 RTC 驱动测试覆盖 2000—2099 年全部 36,525 天、正常复位保持、旧时间迁移、错误时钟配置、超时和写入失败、跨午夜读取、自动 GPS 校时兼容。
- 生产日历编辑函数测试覆盖月末和闰年、范围限制、草稿取消、最终保存、写入失败重试、GPS 过期/非法日期、UTC+8 不重复转换。
- 按键和菜单测试覆盖去抖、长按加速、时钟回绕、释放停止、上下文取消、事件优先级、积压合并和全部 12 个页面入口。
- LCD 实际绘制代码验证 144 组日历状态转换、48 组设置状态转换与全页重绘像素一致；稳定页面不重复写屏。中文加粗和全部 95 个可打印 ASCII 字符均逐像素检查笔画与字格边界。
- 参数格式增加 1,920 组固定列宽检查；模拟量 GUI、运行时控制安全及 GPS 接收回归通过。
