# 机器人遥控器触摸适配

## 工程与修改范围

当前 EIDE 目标为 `Remoter`，MCU 为 STM32F407ZGT6，编译器为 ARMCC 5，
使用 `USE_STDPERIPH_DRIVER` 和项目中的 STM32 标准外设库。
商家压缩包使用 HAL；本次提取触摸寄存器协议和采样流程，接入当前工程的接口。
当前版本保留标准库，不包含 HAL 库迁移。

项目主要运行关系：

- `1_App/main.c`：外设初始化、启动自检及主循环，主循环调用 `GTP_Service()`。
- `1_App/menu.c` / `gui.c`：按键菜单、监控、IMU/GPS、NRF 设置、文件浏览和画板页面。
  `Draw_Board()` 先初始化画板按钮、启用触摸，再在没有有效校准时启动四角校准；其他页面关闭触摸。
- `2_Platform/platform_nrf.c`：NRF24L01 的配置、状态读取和产品通信。
- `3_Protocol` / `5_Middleware`：FatFs、NMEA、MPU6050 DMP、MultiButton 和 JPEG 支持。
- `5_ModuleDrivers`：ADC/摇杆/数字通道、屏幕、触摸、存储及通信外设驱动。
- `6_Core/stm32f4xx_it.c`：中断分发；触摸 EXTI 只置标志，新增 TIM6 的触摸 10 ms 计时。

生产代码修改包括触摸 I2C、GT911 处理、画板、触摸计时和调试串口文本输出。
LCD 初始化、FSMC、无线通信和存储逻辑沿用现有实现。

## 原理图核对

以下连线按主板 MCU → 32 针 FPC → 交互板 GPT1 接口逐段核对：

| MCU | 主板网络/排线针脚 | 交互板实际功能 | GPT1 针脚 |
| --- | --- | --- | --- |
| PC4 | CPT_IO24 / FPC1-24 | CPT_SCL | 3 |
| PB12 | CPT_IO25 / FPC1-25 | CPT_INT | 6 |
| PC5 | CPT_IO26 / FPC1-26 | CPT_SDA | 2 |
| PG8 | CPT_IO27 / FPC1-27 | CPT_RST | 7 |

主板连接器处的 `CPT_RST` / `CPT_INT` 名称与交互板相反，交互板还注明两者可互换。
按所提供的两张图和相同针脚贯通连接，当前 `PB12/EXTI12=INT`、`PG8=RST` 定义正确。
交互板 SCL/SDA 各有 4.7 kΩ 上拉和 20 Ω 串联电阻。
如实物排线或焊接改版与图不同，应以实测连通关系为准。

## 已修复的触摸路径

1. **复位和 I2C**：SCL/SDA 先释放；RST 拉低后才驱动 INT；使用毫秒延时完成地址选择、
   复位与同步。默认选择 7 位地址 `0x5D`（线上写地址 `0xBA`），探测失败再尝试 `0x14/0x28`。
   删除从 EEPROM 示例遗留的 1000 次地址应答等待，正常读写最多重试两次。
2. **读取完整帧**：读 `0x814E` 状态，仅当 bit7 就绪才读 `0x814F` 起的 `8 × 触点数` 字节。
   验证点数、坐标范围、ID 和重复 ID 后，在 LCD 绘制前清除就绪标志。
   非就绪帧不清状态，等待下次轮询；异常帧取消笔迹，避免部分数据触发绘制或按钮。
3. **中断与轮询**：EXTI 提示立即采样，TIM6 提供 10 ms 兜底轮询，实际 I2C 和画图均在主循环中执行。
   200 ms 没有新有效帧时取消当前接触，不执行按钮释放命令。
   轮询依赖已有 TIM6 正常运行，以及主循环能够及时返回；它不保证硬件上的固定采样率。
4. **坐标映射**：画板使用四角共同拟合，通过拟合残差和相对控制器配置的面积比例检查，
   选择普通仿射映射、原始 X 半周期回绕修正或原始 Y 半周期回绕修正。
   校准采集在方向转换和名义分辨率过滤之前进行。
   保留控制器当前通道配置，`UPDATE_CONFIG=0`，不会下发开发板的玻璃配置表。
5. **多指与按钮**：按 GT911 Track ID 保存笔迹，验证整帧后处理抬起。
   工具栏只由起始按在工具栏的那根手指控制，其他手指画画或抬起不会取消它。
   从画布滑入工具栏不触发按钮，滑出原按钮会取消操作；按下和释放使用一致的半开区间边界。
6. **画板绘制**：各次绘制显式设置笔色；清屏、按钮重绘、橡皮擦结束恢复笔色。
   统一绘制连续线段并裁剪每个笔刷矩形，短按可见、粗笔居中、橡皮连续，四边不会越界或覆盖工具栏。
   离开画布再进入时从新点开始，避免跨工具栏连线。

商家触摸参考文件为压缩包中的 `lcd/gtxxx.c`、`lcd/lcd_touch.c`、`lcd/bsp_lcd_tp_i2c.c`。
商家显示驱动、字库、SRAM、LED 等内容未加入工程。
GT911 就绪位可能晚于中断出现的行为，也与 [Linux 上游 Goodix 驱动](https://github.com/torvalds/linux/blob/master/drivers/input/touchscreen/goodix.c) 中的等待处理一致。

## 现场反馈对应的修改：FIELD-CAL-3

现场已确认：工具栏和静态界面正常，只有笔迹左右半屏错位，中部偏左有不到 1 cm 的竖条空缺。
GT911 启动日志为 `911_1060`、`800x480`、`module=0D`、`X2Y=1`、`scan=5`。
这些寄存器值能确认通信和当前配置，不能单独证明触摸玻璃相对 LCD 的坐标原点。
上一版直接采用“原始坐标对应扫描模式 3”的假设，缺少实物验证；新画板通过校准替代这个假设。

`FIELD-CAL-2` 实物日志进一步确认：中心第 5 点反复上报 `n=2`，触发单指采样拒绝；
最后虽然接受了中心采样，三点拟合在右下角的误差为 `(14,-36)`，中心误差为 `(53,-7)`，
超过原来的 24 像素门限而进入 `CAL FAIL`。期间 `io=0`、`bad=0`，服务仍在轮询。

`FIELD-CAL-3` 使用四个角目标 `(80,80)`、`(720,80)`、`(80,400)`、`(720,400)`，
取消中心必点目标，四个样本共同进行最小二乘仿射拟合。
先尝试普通映射，再分别尝试原始 X、原始 Y 加半周期取模，周期来自对应控制器范围。
每个候选必须同时满足：数据非退化、四角两轴残差不超过 24 像素、
控制器配置范围经变换后的面积为 LCD 面积的 0.5～1.5 倍。
面积检查利用了当前配置的名义范围，避免仅用四角拟合时把发生回绕的窄坐标跨度错误拉伸至全屏。
当前实现假设控制器配置范围大致覆盖整屏；不适用于配置范围和实际输出比例严重不符的装配。
校准时计算浮点系数，正常报告使用 Q16.16 定点乘加。

重放本次四角数据 `(323,420)`、`(499,385)`、`(333,51)`、`(494,56)`：
普通模型面积比例为 3.467，被拒绝；X 回绕模型为 0.925，四角最大拟合残差为 10 像素，
第 4 点抬起后接受 `model=1, period=800` 并进入画板。
这些残差来自拟合样本，不代表全屏实测精度，也不再包含独立中心点检查。
校准不能修复传感器局部断区；中心区域单指被控制器分成两个 ID 的现象仍需实物定位。
新增全触点日志用于观察该现象，正常多指处理继续按 ID 分别绘制。
不符合任何候选模型时仍显示 `Calibration check failed`，继续输出原始坐标。

采样要求同一根手指稳定接触至少三个有效帧，抬起后接受该点。
短按采样不足、多指、明显移动会要求重按当前目标；通信失败或超时取消本次采样。
可能跨越原始 `799/0` 边界的微小抖动按循环距离平均，避免把相邻点平均成半屏坐标。
正常绘制使用通过检查的变换，再检查屏幕边界；仅容忍 12 像素边缘误差并裁剪到有效像素。

校准存于 RAM，退出再进入画板时复用；重启或改变扫描模式后重新校准。
画板页面按实体 **OK** 键可重做校准，**BACK** 返回菜单。
`GTP_NATIVE_MIRROR_X/Y` 仅作用于保留的未校准兼容路径，不会覆盖画板实测结果。
芯片识别继续限定为 GT911、最多五指。

## 串口与 MobaXterm

调试串口为 **115200、8 数据位、无校验、1 停止位、无硬件流控**。
工程中文字面量使用 GBK；`fputc()` 通过 `debug_text.h` 和已经参与链接的 FatFs `ff_convert()`
把 GBK 转为 UTF-8，并为独立 LF 补 CR，已有 CRLF 不重复补 CR。
LCD 字库和原始串口字节接口仍使用各自现有协议，新增中文 `printf` 字面量应继续使用 GBK。
USART1 的接收 ISR 只处理 RXNE；此次关闭其未处理的 IDLE 中断源，避免收到终端字符后持续进入中断。

在 MobaXterm 中设置 **Settings → Configuration → Terminal → Charset → UTF-8 (unicode)**。
已有串口会话的字符集可能覆盖全局设置，需要同时检查该会话的 Terminal settings，然后重新连接。
设置入口和会话覆盖规则见 [MobaXterm 官方说明](https://mobaxterm.mobatek.net/documentation.html)。
新设置配合本版固件使用；旧固件仍输出 GBK，不能靠切换到 UTF-8 正确解码旧日志。

启动可见以下标记，用于确认实际刷入本版固件：

```text
[DEBUG] UART1 115200 8N1; text=UTF-8; newline=CRLF
<<-GTP-INFO->> touch build: FIELD-CAL-3 ...
```

画板日志不依赖 `GTP_DEBUG_ON`：

| 标记 | 用途 |
| --- | --- |
| `PAGE enabled` | 确认已启用画板触摸服务 |
| `RAW` / `MAP` | 每条触点记录的原始/映射坐标，最多每 100 ms 一组；RAW 含 slot、ID、size，校准时只有 RAW |
| `CAL P1` … `CAL P4` | 各目标的平均原始坐标、屏幕目标和样本数 |
| `CAL model=... area-gain` / `corner residual` | 候选映射的面积比例（千分比）和四角最大拟合残差 |
| `CAL PASS model=0/1/2` | 分别为普通映射、X 回绕、Y 回绕，已通过四角残差和比例检查 |
| `CAL FAIL` | 四角数据未通过检查，可按 OK 重试，保留日志供定位 |
| `DROP` | 无效帧原因及第一条记录原始坐标；异常时限频输出 |
| `RUN` | 每 2 秒输出时钟、IRQ 次数、轮询数、就绪帧数、无效帧数、I2C 错误数和最近状态 |
| `UP` / `CANCEL` | 正常抬起 / 有效帧超时取消 |

I2C 状态确认先于串口日志及 LCD 绘制，避免慢速输出占住 GT911 报告缓冲区。
`RUN` 的累计统计用于观察变化趋势；它依赖 TIM6 和主循环正常运行。
若触摸时 `poll` 持续增加但 `ready` 不增加，优先检查控制器就绪状态；`io` 增加表示总线访问失败。
`irq` 不增加但 `ready` 增加说明轮询仍在工作，可进一步检查中断线路。

## 验证与上板检查

主机测试见 `7_Test/host/README.md`，直接测试生产解析器及画板，未向固件加入测试桩。
EIDE 构建使用现有 `build/Remoter/builder.params`，产物为
`VSCode EIDE Project/build/Remoter/Remoter.hex` 和 `.bin`。

2026-09-05 验证结果：主机回归通过；EIDE 全量重编译 93 个 C 文件、1 个汇编文件通过，
0 错误。12 条编译警告来自未修改的 FatFs 测试、NMEA 和 JPEG 代码，触摸模块无新增 ARMCC 警告。
最终 BIN 为 294,020 字节，RAM 占用 66,336 字节。
全量构建日志位于 `VSCode EIDE Project/build/Remoter/touch-build.log`。

上板后按以下顺序检查：

1. 刷入 EIDE 的 `build/Remoter/Remoter.hex`，串口设置 UTF-8，确认 `FIELD-CAL-3` 标记和 GT911 信息。
2. 打开画板，依次按住四角的红色十字约 0.2 秒后抬起；第 4 点通过后自动进入画板，没有第 5 点。
   查看 `CAL PASS`，在可画区域四角短按，再横向穿过原先的竖条和中线，检查连续性与方向。
3. 两指/五指同时移动、交错抬起，确认各轨迹独立；短按后换位置，不应连接前后笔迹。
4. 选择颜色、清屏后再画；粗笔与橡皮沿四边滑动，检查颜色、边界及工具栏。
5. 按住工具栏时另一指画画/抬起；滑出按钮后释放；退出再进入画板，检查无误触发或残留笔迹。

如果校准失败或笔迹仍异常，保留 `CAL P1` 到 `CAL P4`、模型检查、`CAL PASS/FAIL`，
以及缓慢穿过竖条时的 `RAW/MAP` 和前后两条 `RUN`。这些日志用于判断映射问题还是控制器原始数据不连续。

本次未烧录设备。主机测试不能替代 I2C 波形、真实中断行为、贴合方向或触摸流畅度验证。
