# 开机检测说明

进度按 `已结束的检测项 / BOOT_ITEM_COUNT` 计算。通过、失败、未测试均属于已结束，但分别计数；运行中和重试不增加进度。100% 表示清单处理完毕，不表示所有硬件通过，也不是剩余时间估计。恢复 REMOTER 开机动画：约 300 ms 装饰动画期间进度保持 0%，随后由实际检测驱动进度条。没有逐阶段动画延时；结束后无故障时保留汇总 1.2 秒供阅读。

## 结果与故障处理

- `PASS`：这一行明确描述的检测通过。
- `FAIL`：检测失败，保留该行及原因，不会被后续成功覆盖。
- `NOT TESTED / 未测试`：未检测或因前置设备失败而无法检测，不能计为通过。
- 任意失败或未完成：最终红色故障提示停留，必须重新按下并松开实体 OK 键才进入菜单；上电时一直按住 OK 不会跳过故障页。进入主菜单后仍显示各类结果数量，串口保留完整明细。
- 存在未测试项：最终显示 `CHECKS COMPLETE` 和未测试数量，不显示绿色 `READY` 或“无线控制已经在线”。
- 开机页使用 MCU 内置 ASCII 字体；“未测试”三个字也存于 MCU 内部，不依赖正在接受检测的外部 Flash 字库。

## 自动检查的范围

| 项目 | 实际依据 | 不代表什么 |
|---|---|---|
| MCU 时钟 | HSE/PLL 就绪位和系统/总线时钟回读 | 不覆盖启动代码执行前的致命故障 |
| 外部 SRAM | 1 MiB，分块 8/16 位正反图案写入、比较、恢复并验证 | 不是完整的地址线混叠/March 测试 |
| W25Q128 Flash | 两次 JEDEC ID（期望 EF4018）、忙状态超时、三个地址的重复只读采样 | 未验证全部内容正确性、擦写能力或寿命 |
| EEPROM | AT24C08 的 7 位地址 0x50 应答、首个 256 字节逐字节重复读取 | 不验证容量/写入寿命，也不访问地址重叠的 AT24C256；全 FF 允许通过 |
| RTC | 有限等待晶振启动、初始化/同步结果、子秒计数变化 | 不验证长期精度和断电保持 |
| ADC1 / ADC3 | 新 DMA 传输完成、无 DMA 错误、7+3 通道 12 位样本 | 不验证摇杆全行程或电池电压校准精度 |
| MPU6050 | DMP 初始化/固件回读，并等待实际 FIFO 数据 | 不等同于工厂传感器精度自检 |
| 触摸控制器 | 沿用现有初始化、版本/配置通信结果 | 不检测触摸准确度；不改触摸算法或校准流程 |
| SD 卡 / 文件系统 | 有限次数卡命令初始化、只读挂载分区/FAT 元数据 | 不写文件、不格式化、不检测全盘介质 |
| NRF24L01 | SPI 寄存器读写比较及频道/功率/速率/启用状态回读 | 不代表机器人接收端可达或无线链路通过 |
| GPS | 接收缓冲区内存在完整且校验和正确的 NMEA 句子 | 不要求室内定位成功，也不验证定位精度 |
| 运行定时器 | TIM2/3/5/6 计数变化、TIM5/6 中断活动 | TIM4 是编码器，静止不计数不报故障 |
| 参数装载 | Flash 可用才读取；原有默认值/旧参数迁移流程中的写入增加回读错误反馈 | 不向 Flash 写入自检图案 |
| MCU 内存采样 | 编译器分配的 1 KiB RAM 逐位正反图案、4 个内部 Flash 常量的实际读取 | 不代表全部 RAM 测试或固件完整性校验；不会写固定 RAM 地址 |

需人工操作或外部设备配合的项目在启动时仍显示“未测试”，可从新增 **Hardware Tests** 菜单实际运行，操作和判据见 [硬件测试与 EEPROM 菜单说明](HARDWARE_DIAGNOSTICS.md)。Flash、EEPROM、SD 写入验证也放在该菜单按需执行，避免每次上电消耗擦写寿命。菜单保存本次上电的手动测试结果；开机汇总保留启动时的检测快照，不被手动测试覆盖。

原理图中 PD12/PD13 用作 SRAM A17/A18；虽然源码保留 TIM4 编码器配置，不能因此把它当作已接入的物理编码器。新增按键测试验证四个实体菜单键和六路 DCH，不改动 SRAM 引脚复用。

EEPROM 单字节读取按 STM32 [RM0090](https://www.st.com/resource/zh/reference_manual/DM00031020.pdf) 的 ACK/ADDR/STOP 顺序执行，并对 BUSY、SB、ADDR、BTF、RXNE 等等待设置退出条件。NACK、总线错误或超时后恢复 ACK 并复位 I²C 外设状态，不会无限等待。仍使用项目现有标准外设库。

## 存储边界

- 删除了 `INER_SRAM_ADDR` 以及对 `0x20001000` 的固定地址写入。
- SRAM 自检只访问外部 SRAM `0x6C000000–0x6C0FFFFF`，在挂载文件系统、启动应用消费者之前执行；备份使用编译器分配的局部数组。每个块在进入下一块前恢复，包括检测失败路径。硬件本身损坏时不能保证恢复成功，会报告失败。
- Flash、EEPROM 开机探测函数没有擦除或写入存储内容。EEPROM 随机读取中的“写方向”仅设置读取地址指针，不发送存储数据。
- 原有参数默认值/旧版本迁移仍可能更新参数专用扇区，这是参数管理行为；它不属于破坏性自检，也不写 SPI 文件系统分区。Flash 探测失败时跳过该流程，在 RAM 中使用默认参数。

## 128 Mbit Flash 当前用途

`W25Q128 = 128 Mbit = 16 MiB`（通常简称 16 MB）。不是 128 MB，也不是 1218 MB。

- 遥控器参数：摇杆通道上下限/中点/反向、各项偏好、NRF 设置等，保存到专用 4 KiB 扇区 `0x5FF000`。
- 中文点阵字库：从 `1254 × 4096 = 0x4E6000` 开始，普通中文显示按需读取。
- 写入测试专用扇区：`0x5FE000–0x5FEFFF`，在中文字库末尾 `0x5E5900` 与参数扇区之间。只有检查整扇区原先全 FF 才允许执行，发现占用不会擦除。
- 现有布局前 6 MiB 为资源/参数预留，后 10 MiB 为旧 SPI FatFs 分区。SPI 文件系统菜单/开机挂载已去除，旧分区内容保留，不再作为文件浏览入口。
- 主程序固件存放在 STM32 内部 Flash；SD 卡是当前文件系统菜单的存储设备。

## 验证

主机测试：在仓库根目录运行 `py -3.9 7_Test/host/run_boot_tests.py`（需要 GCC，可将 GCC 路径作为参数传入）。它验证全部失败位置、进度去重、未测试分类、NMEA 校验和 SRAM 数据恢复/范围边界，并运行存储探测、EEPROM 字节写入和新增诊断测试。测试直接编译生产代码，注入缺件/NACK、等待超时、读回错误、存储占用、文件短读写/清理失败、UART 无回环、无线无 ACK/坏包/取消/超时等条件，检查存储边界和外设状态恢复。

编译和模拟测试不能替代实机验证。烧录后应确认动画、实际检测进度、故障停留与菜单入口，再按测试菜单提示逐项操作。可用既有参数、文件和字库检查跨启动保留情况；任何诊断都不需要格式化存储设备。
