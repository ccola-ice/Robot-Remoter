## 两端配套使用

遥控器 EIDE 工程与 `D:\[Desktop]\新建文件夹\02_Robot_Chassis` 接收工程必须同时更新。本次没有烧录硬件。

- 射频默认：频道 40、2 Mbps、5 字节地址 `34 43 10 10 01`、固定 32 字节、自动 ACK、16 位硬件 CRC。菜单改变发射端频道/速率后，接收端需要使用相同设置。
- 转向沿用目标航向控制。每次使能捕获机器人当前航向；右摇杆左右控制相对此航向的目标偏移，居中保持使能时的航向。
- 左摇杆：CH03 为 X，CH02 为 Y；右摇杆 CH06 为目标航向。沿用现有界面横轴方向修正。校准上下限、中位、正反向、微调用于真实控制，5% 中位死区。
- 操作条件：关键自检通过、ADC 正常更新、电池电压不低于设置值、无线 ACK 新鲜、停留在机器人控制页面。松开 DCH1、摇杆居中持续 500 ms，再按住 DCH1 使能；松开即发送停止包。DCH1 对应 PD6、低电平有效。
- 离开控制页面、ADC 停止、主循环长时间停顿、低电压、无线故障都会解除使能；恢复后须重新松开 DCH1 并回中，不能因一直按住按钮而自动恢复运动。
- 接收端只开放手动模式。原无线数据直接启动导航/跟随的入口已关闭，待这些功能有独立安全状态机后再启用。
- 接收端上限初始设为每 20 ms 的 20 个编码器计数，由 `RECEIVER_WHEEL_CAP` 配置。这不是已标定的 m/s；实际速度、方向、制动距离需要台架测量。

## 控制帧 v1

大端编码，有符号字段使用 16 位补码。权威实现为两端相同的 `1_App/robot_control_protocol.h`。

| 字节 | 字段 | 范围/含义 |
|---|---|---|
| 0–9 | 旧格式保留 | 全零，旧协议的模式和速度上限均为零 |
| 10–11 | 标识 | ASCII `RC` |
| 12 | 版本 | 1 |
| 13 | 标志 | bit0 为使能，其余位零 |
| 14–15 | 序号 | 每个新发送包递增，16 位回卷 |
| 16–17 | X | −1000…1000，归一化平移输入 |
| 18–19 | Y | −1000…1000，归一化平移输入 |
| 20–21 | 航向 | −1800…1800，0.1°，相对本次使能航向的目标偏移 |
| 22–23 | 速度上限 | 0…1000，相对接收端配置的轮速上限 |
| 24–25 | 数字输入 | bit0…5 对应 DCH1…6，低电平输入置位；其余位零 |
| 26–29 | 保留 | 全零 |
| 30–31 | CRC | CRC-16/CCITT-FALSE，初值 0xffff，多项式 0x1021，覆盖字节 0…29 |

未使能帧的 X、Y、航向和速度上限必须全部为零。使能帧必须包含 DCH1 有效标志和非零速度上限。任何不符合版本、范围、保留位、CRC 的帧都不能进入运动控制。

遥控器目标周期为 20 ms，主循环发送，单次射频等待最长 30 ms，不在中断中等待 IRQ 引脚。主循环延误不补发历史命令。接收端只接受向前推进的序号；重复、乱序、损坏帧不能延长有效期。200 ms 内没有新合法帧立即清 PID 累积和 PWM；失联后先收到未使能帧，才允许再次使能。IMU 超过 300 ms 未更新也会停车。

无线 ACK 仅证明射频硬件应答，不代表机器人已执行命令，更不代表收到速度、电量等遥测。当前机器人尚未实现这些遥测的回传，因此界面显示 `NO TELEMETRY`。CRC 和序号用于传输完整性和新鲜度，不提供身份认证；固定地址也不提供设备配对或防恶意注入能力。

NRF 上电到收发模式的稳定等待和 CE 脉宽按 [Nordic nRF24L01 产品规格书](https://devzone.nordicsemi.com/cfs-file/__key/communityserver-discussions-components-files/4/content.pdf) 设置；驱动采用 1.6 ms 上电等待、20 µs CE 脉冲。

## 其他修复

- 参数使用两个独立 4 KiB 扇区轮换，CRC/长度/schema/序号校验，提交标记最后写入；保留旧格式迁移，不持久化 RAM 指针。A：`0x5ff000`，B：`0x5fd000`，原诊断扇区 `0x5fe000` 不变。
- 所有参数加载及保存检查范围、枚举、有限浮点数和校准顺序。没有校验和的旧格式只能检查字段合法性，无法识别所有仍落在合法范围内的损坏。
- SPI Flash 修正跨页、长写入截断及地址边界；故障黏性记录，出错后停止后续写操作。恢复需要成功复检。
- SD/SDIO/FatFs 的命令、DMA 和忙等待都有上限；错误上传，不再无限等待或报告虚假成功；请求做容量边界检查。
- GPS 限定字段写入长度，修正北斗定位状态，DMA 完成块进入软件队列。位置/时间分别跟踪 3 秒新鲜度，溢出使旧数据失效，只有新的有效完整日期才用于校时。
- 系统时钟改为真正的 1 ms，微秒延时使用 DWT；修正 TIM5 任务频率、共享标志原子消费和 MPU 时间接口。驱动不再任意改变全局中断分组。
- GUI 使用有界格式化，移除假在线和假遥测；尚无执行逻辑的 PPM、接收机低压报警、模型类型、闹钟等设置标为 `UNAVAILABLE` 并禁止编辑。机器人控制的中位/使能保护始终有效。
- 发射端电池 ADC 按硬件 VIN/2 分压换算，并使用电压校准参数。原“TX battery warning”现明确为控制低压截止值，默认 3.7 V；需用实测电压校准。

主机测试使用实际生产函数或生产文件，替换硬件寄存器/I/O；不能替代硬件时序和机械运动试验。

## 上板验收与剩余限制

先断开电机动力或架空底盘：核对 DCH1 和三个控制轴方向、ADC 校准、实际电池电压、NRF 应答及启停；验证拔掉遥控器电源/NRF/IMU、遮断链路、保持按钮重连时的 PWM 和动作。测量 200 ms 失联门限对应的实际停机延迟与制动距离，再确定轮速上限。

CPU 异常路径的 PWM 清零和看门狗复位行为需要示波器/上板验证。软件不能确认电机驱动输入浮空、电源掉电、MCU 失效时的硬件安全状态；硬件急停和驱动使能隔离仍需独立验收。

原理图中两颗 EEPROM 的地址覆盖风险需要核对实物型号和地址脚连接。本轮没有通过修改固件假定该硬件冲突已经解决。机器人遥测、设备配对/认证和尚未实现的菜单功能不属于已经完成的功能。

接收工程的 GPS USART6 和 TIM8 编码器都占用 PC6/PC7。手动控制版本禁用了接收端 GPS 初始化/解析，保留编码器；恢复导航前需要重新分配引脚并核对接收板原理图。遥控器本身的 GPS 功能正常保留。
